# 시각요소 점검 기준

**RFP의 작성 지침이 있으면 그것이 우선이다.** 아래 수치는 RFP에 정함이 없을 때 쓰는 권고 기준이다.

## 글자 크기

제안서는 발표용(화면 투사)과 열람용(인쇄·PDF 제출, 평가위원이 직접 읽음)으로 기준이 다르다. 국내 제안서는 대부분 열람용이고 텍스트 밀도가 높다. 슬라이드를 보고 어느 쪽인지 판단하고, 애매하면 열람용 기준을 쓴다.

| 요소 | 열람용 | 발표용 |
|---|---|---|
| 헤드라인(제목) | 20~28pt | 28pt 이상 |
| 본문 | 12pt 이상 (10~11pt는 "작음", 10pt 미만은 "판독 곤란") | 18pt 이상 |
| 표 내부 | 10pt 이상 | 14pt 이상 |
| 각주·출처 | 8pt 이상 허용 | 10pt 이상 |

- `analyze_pptx.py`의 `min_body_pt`는 출처·각주·바닥글을 빼고 계산한 본문 최소 크기다
- `autofit_scale`이 80% 미만이면 PowerPoint가 넘치는 글자를 강제로 줄인 것이다. 작성자도 모르는 경우가 많으니 꼭 짚는다
- 한 슬라이드에 글자 크기가 4종 이상 섞이면 위계가 흐려진다

## 텍스트 밀도

| 슬라이드당 글자 수(공백 제외) | 판단 |
|---|---|
| ~250 | 양호 |
| 250~400 | 열람용으로는 허용, 핵심 강조(굵게·색·박스) 필요 |
| 400 이상 | 과밀. 분할하거나 표·도식으로 전환 권고 |

- 글머리표 위계가 3단계를 넘으면 구조를 다시 짜야 한다는 신호다
- 글자만 있고 시각요소(표, 차트, 도형 도식, 그림)가 하나도 없는 슬라이드가 연속되면 지적한다

## 도형·도식

내용 유형에 맞는 도식을 쓰는지 본다.

| 내용 | 적합한 표현 |
|---|---|
| 단계·절차 | 화살표 프로세스(Chevron), 단계별 박스 |
| 일정 | 간트 차트, 타임라인 |
| 조직·역할 | 조직도, RACI 표 |
| 구조·아키텍처 | 계층 박스, 레이어 다이어그램 |
| 비교·대안 | 비교표, 2×2 매트릭스 |
| 인과·관계 | 흐름도, 로직 트리 |
| 목표 체계 | 피라미드, 비전-전략-과제 체계도 |

- 장식용 도형(의미 없는 아이콘, 3D 효과, 과한 그라데이션)은 오히려 감점 요인
- 화살표 방향과 읽기 순서가 일치하는가, 도형 크기와 정렬이 고른가

## 표

- 비교·대응·요구사항 추적에는 표가 가장 명확하다 (특히 "RFP 요구사항 ↔ 제안 내용 대응표"는 평가위원이 매우 반긴다. 없으면 추가를 권고한다)
- 열 7개, 행 12개를 넘으면 분할이나 요약을 검토
- 머리글 행 구분(색·굵게), 숫자 오른쪽 정렬, 단위 표기
- 셀 안에 긴 문장이 들어가 있으면 표의 장점이 사라진다

## 그래프

| 보여주려는 것 | 적합한 유형 | 피할 것 |
|---|---|---|
| 시간에 따른 추이 | 꺾은선, 세로 막대 | 원형 |
| 항목 간 비교 | 가로·세로 막대 | 3D 막대 |
| 구성비 | 100% 누적 막대, 원형(5개 항목 이하) | 항목이 많은 원형 |
| 상관관계 | 분산형 | — |
| 목표 대비 실적 | 막대 + 목표선, 불릿 차트 | — |

- 제목이 메시지를 담는가("매출 추이"가 아니라 "3년간 매출 2배 성장")
- 축 제목·단위·기준 연도·범례·출처가 있는가
- 축이 0에서 시작하지 않아 차이가 과장되지 않았는가
- 강조할 데이터만 색으로 구분하고 나머지는 회색 계열로 두었는가
- 그림으로 붙인 차트(캡처 이미지)는 해상도가 낮거나 출처가 빠지기 쉽다

## 일관성

- 폰트 종류: 문서 전체 2~3종 이내 (스크립트의 `font_families` 참고)
- 색상: 주조색 1~2개 + 강조색 1개 + 회색 계열
- 제목 위치, 여백, 페이지 번호, 로고 위치가 슬라이드마다 같은가
- 익명화 요구가 있는 RFP라면 로고·회사명·제품명 노출을 반드시 확인
